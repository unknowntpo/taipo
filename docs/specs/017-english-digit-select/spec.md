# Spec 017: 英文候選直接用數字鍵選字

Status: Accepted（2026-10-27，使用者選定下方兩個決定）
Date: 2026-10-27
Traceability: enforced
Builds on: Spec 014（數字鍵選字）、Spec 003（中英混打）
Amends: Spec 014 簡化審查第 2 點（「不做數字鍵直接選字」）

## Intent

第一個候選是英文單字、而且數字鍵接上去不像注音時，使用者不必先按 ↓，直接按 `1`–`9` 就送出候選窗那一列。打注音時數字鍵仍是注音鍵。

## Evidence

2026-10-27 使用者回報並重現：打 `lexus`，候選窗顯示 1–3 編號；按 `3` 想選 `lexus`，組字卻變成 `lexus3`，候選變成「奧理、襖理、lexus3」。

原因：Spec 014 規定數字鍵只在 ↓／↑ 之後選字；之前 `3` 是大千的三聲鍵。

## Example

2026-10-27 用 `swift run taipo explain` 在 bundled lexicon 上擷取：

| 組字 | 第一候選 | 按鍵 | `buffer + 數字` 的解讀 | 結果 |
| --- | --- | --- | --- | --- |
| `lexus` | plexus（英文，1 個修正） | `3` | 奧理（2 個修正）；`lexus3` 不是任何注音開頭 | 送出第 3 列 `lexus` |
| `lexus` | plexus | `9` | 同上 | 只有 3 列：按鍵被吃掉 |
| `up` | up（英文） | `4` | 印（無修正） | 加進組字（四聲） |
| `hellosu` | hellos（英文，1 個修正） | `3` | hello 你（無修正） | 加進組字（三聲） |
| `a` | a（英文） | `8` | `a8` 是「ㄇㄚ」的開頭 | 加進組字 |
| `ok` | ok（原樣字母，不是字典字） | `8` | — | 加進組字（行為不變） |
| `ji3` | 我（中文） | `3` | — | 加進組字（行為不變，Spec 014 N1） |

## Behavior

1. **直接選字**：未在選字狀態（Spec 014）時，若同時成立：
   - 第一個候選是英文字典字或使用者詞（`source` 為 lexicon、user、learned，語言 en；不含原樣字母、混打句、未完成尾巴），
   - 數字鍵 `1`–`9` 不延續中文（Behavior 2），
   則數字送出目前頁第 N 列，規則同 Spec 014 Behavior 2（學習同 Enter；該列不存在時按鍵被吃掉）。
2. **延續中文**（`Decoder.continuesChinese`）：以下任一成立就當作注音鍵：
   - 組字中最後一個聲調鍵（空白、`6` `3` `4` `7`）之後的鍵加上數字，是 lexicon（或使用者詞）某個注音讀音的開頭。例：`a` + `8` = ㄇㄚ。
   - `buffer + 數字` 解碼後第一名是中文、沒有修正、不是原樣字母（含結尾為中文的混打句與未完成尾巴）。例：`hellosu` + `3` = hello 你。
3. **排名**：輸入字母剛好是英文字典字時，它排在所有經過修正（插入、刪除、替換、對調）的英文候選之前。這是現有行為（`Decoder.rank` 先排無修正），本 spec 以測試固定。輸入不是字典字（如 `lexus`、`teh`）時，原樣字母仍是最後一列，不變。中文排名不變。
4. **其他**：`0`（ㄢ）永不選字。英數模式（Spec 013）、選字狀態（Spec 014）行為不變。

## Acceptance

### Behavior
- A1：具名測試：打 `lexus` 後按 `3`，送出候選窗第 3 列（`lexus`），組字清空，並寫入使用者詞庫（同 Enter）。
- A2：具名測試：正向對照，逐鍵打 `ji3`→我、`su3`→你、`5j/ cl3`→中好，每個數字都加進組字。
- A3：具名測試：第一候選是英文，但數字構成中文讀音時加進組字：`up`+`4`→印、`hellosu`+`3`→hello 你。
- A4：具名測試：`lexis`、`plexus`、`hello`、`baht`、`froward` 的字典字排第一（後兩個是罕用字，與常用字 bath、forward 只差一次對調，只靠分數會輸），其後英文候選都有修正；邊界另一側：`teh` 不是字典字，原樣字母是最後一列。
- A5：[manual] 真機：打 `lexus` 按 `3` 送出 `lexus`；打 `ji3` 照常出「我」。

### Failure and retry
- A6：具名測試：`lexus` 後按超過最後一列的數字，按鍵被吃掉，組字與候選不變。
- A7：具名測試：第一候選是原樣字母（`ok`）時，`8` 加進組字。
- A8：具名測試：第一候選是混打句（`su3hello`）時，`3` 加進組字。
- A9：具名測試：第一候選是英文 `a`，`8` 是「ㄇㄚ」的開頭，加進組字；再按空白得到 ㄇㄚ 的中文（「嗎」）。
- A10：具名測試：英文單字後按 `0` 加進組字（ㄢ）。

### Budget
- A11：[measure] 對 bundled lexicon 的中文讀音逐鍵輸入，數字被當成選字的讀音數必須為 0。執行：`TAIPO_SWEEP_STRIDE=10 swift test --filter lexiconSweep`。2026-10-27 結果見下方「量測」。
- 只有第一候選是英文字典字時，數字鍵多一次 trie 查詢，必要時多一次解碼。

### Observability
- 不適用：候選窗本身。

## 簡化審查

1. **質疑需求**：使用者回報真實失誤；英文候選旁的 1–9 編號本來就暗示可以按。
2. **刪除**：不改候選窗編號；不讓原樣字母、混打句觸發直接選字；不改排名程式（排名早已先排無修正的字）。
3. **簡化**：判斷只看第一候選與 `Decoder.continuesChinese`，選字沿用 Spec 014 的路徑。
4. **縮短驗證週期**：A1–A4、A6–A10 單元測試；A11 lexicon 掃描；真機只驗 A5。
5. **自動化**：A11 為選擇性執行的測試（環境變數開啟），不進預設 `swift test`，因為完整掃描需數十分鐘。

## Non-goals

- 把 `lexus` 等專有名詞加進英文詞庫。`lexus` 不在 SCOWL 詞庫中，所以它是原樣字母、排在最後；需要時由使用者選一次後學習。
- 選字狀態前隱藏 1–9 編號（Spec 014 Non-goal）。
